## 2. Correcciones aplicadas (sesión)

### Bloqueante de compilación

| Archivo | Corrección |
|---|---|

| `lib/aves_web/controllers/api/category_controller.ex` | Misma cláusula redundante eliminada |

### Bug latente: updates atómicos de Ash (`actor.rol`)

La policy de `bird.ex` y `category.ex` usaba `expr(actor.rol in [...])`. En el
**update atómico** (vía estándar de Ash) esa referencia explota con
`Invalid reference actor.rol`. Forma correcta (como ya usaba `report.ex`):

```elixir
authorize_if expr(^actor(:rol) in [:moderador, :admin])
```

### Bug de contrato: permisos respondían 422 en vez de 403

Los controllers de mauricio mapeaban todo error Ash a `422`. En `helpers.ex`
se agregó (un fix centralizado, sirve a los 6 controllers):

```elixir
status =
  case error do
    %Ash.Error.Forbidden{} -> :forbidden
    _ -> status
  end
```

### Flujo de codegen de Ash (lección importante)

Tocar recursos sin correr `mix ash.codegen` hace que `CheckCodegenStatus`
mate el servidor dev con 500 (por diseño, para evitar esquemas divergentes).
Toda migración de recursos debe generarse con `mix ash.codegen <nombre>`,
que produce migración + snapshots. Las migraciones manuales quedaban
"invisibles" para Ash y provocaban choques de esquema (`duplicate_table`,
FKs dependientes) entre `aves_dev` y `aves_test`. Ambas BD se resetearon
desde cero para dejar todo coherente.
