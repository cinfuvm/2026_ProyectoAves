= UAT — User Acceptance Testing
:toc:
:toclevels: 3
:sectnums:

== 1. Objetivo

El presente documento define las pruebas de aceptación de usuario (User Acceptance Testing, UAT) para el sistema *Bitácora de Aves*.

El objetivo es verificar que las funcionalidades implementadas cumplen con los requisitos funcionales RF-01 a RF-20 definidos para el proyecto.

Las pruebas se realizan desde la perspectiva de los usuarios finales y de los responsables de administración y moderación del sistema.

== 2. Alcance

El UAT contempla las siguientes áreas:

* Cuentas y acceso.
* Catálogo de aves.
* Bitácora de avistamientos.
* Moderación y popularidad.
* Dashboard web y landing page.
* API REST y documentación.

Cada requisito funcional posee al menos un caso de prueba asociado.

== 3. Roles utilizados en las pruebas

[cols="1,3"]
|===
|Rol |Descripción

|Usuario
|Usuario común que puede registrarse, iniciar sesión, consultar aves, registrar avistamientos y administrar su colección personal.

|Moderador
|Usuario encargado de revisar los reportes de fotografías.

|Administrador
|Usuario encargado de administrar usuarios, aves y colecciones mediante el dashboard.
|===

== 4. Resultado de las pruebas

Cada prueba debe registrarse utilizando uno de los siguientes estados:

[cols="1,3"]
|===
|Estado |Descripción

|PASS
|La funcionalidad cumple completamente con el resultado esperado.

|FAIL
|La funcionalidad no cumple con el resultado esperado.

|BLOCKED
|La prueba no puede ejecutarse debido a una dependencia o problema externo.

|N/A
|La prueba no aplica al ambiente evaluado.
|===

== 8. Criterios de aceptación final

El sistema será considerado aceptado cuando:

* Los 20 requisitos funcionales hayan sido evaluados mediante los casos UAT correspondientes.
* Los casos críticos no presenten resultados `FAIL`.
* No existan errores críticos que impidan utilizar las funcionalidades principales.
* Los usuarios puedan completar los flujos principales del sistema.
* Los permisos asociados a usuario, moderador y administrador funcionen correctamente.
* La API REST pueda ser utilizada por el dashboard y la aplicación móvil.
* La documentación OpenAPI se encuentre disponible y actualizada.
* La colección Bruno permita ejecutar las pruebas definidas para los endpoints.
* Los resultados hayan sido registrados y revisados por el equipo responsable.
